# Подбор печати для произвольного STL

`POST /api/print-plans/analyze-stl` принимает один multipart-запрос с STL и параметрами.
Здесь нет сопоставления с `research-models.json`: форма детали передаётся настоящему слайсеру.
Результат — лучший из шести рассчитанных вариантов по заданному приоритету и ограничениям.
Расчёт не обещает глобальный оптимум среди всех настроек или подтверждённую прочность детали.

## Принтер и материалы

Первый поддержанный принтер — **Bambu Lab A1 mini, штатное сопло 0,4 мм,
текстурированная PEI-пластина**. Рабочая область 180 × 180 × 180 мм, предел температуры
стола 80 °C — по [спецификации Bambu Lab](https://store.bblcdn.com/6cddc28fcb5a4a34975cfc7a23c83491.pdf).

Используются установленные системные профили Bambu Studio: машина A1 mini 0.4,
процесс `0.20mm Standard @BBL A1M` и `Generic PLA/PETG/TPU @BBL A1M`.
Наследование и `include` разрешаются до полных JSON-конфигураций, как требуется
[официальным CLI](https://github.com/bambulab/BambuStudio/wiki/Command-Line-Usage).
Профили и пользовательские настройки Bambu Studio не изменяются.

Из каталога материалов берутся плотность и диапазоны температуры. Температура выбирается
в середине диапазона (стол не выше 80 °C); скорости экструзии ограничиваются паспортным
максимумом, относительные скорости сохраняются. Ограничение объёмного потока остаётся
из универсального профиля Bambu: калибровка конкретной катушки ещё не поддерживается.
Поэтому результат обозначен как оценка и показывает версию слайсера.

В этом режиме доступны PLA, PETG и TPU 95A. Каталог остальных материалов остаётся
доступен в режиме испытаний образцов. Материал с требованием закалённого сопла,
минимальной температурой стола выше 80 °C или сопла выше 300 °C отклоняется бэком.
Это начальный набор поддержанных профилей, а не перечень всех физически возможных материалов.

## Запрос

| Поле | Значение |
| --- | --- |
| `file` | ASCII или бинарный STL, до 15 МиБ и 100 000 треугольников |
| `materialProfileId` | ID конкретного продукта из `GET /api/materials` |
| `priority` | `MIN_MATERIAL`, `MIN_TIME`, `BALANCED` |
| `layerHeightMm` | 0.12, 0.20 или 0.28: верхний предел слоя для сравнения |
| `minimumInfillPercent` | Целое число от 5 до 80 |
| `minimumPerimeters` | Целое число от 2 до 6 |
| `supportMode` | `AUTO` или `NONE` |
| `maxPrintTimeMin`, `maxMaterialConsumptionG` | 0 — без ограничения, иначе положительное число |

Поддержки создаёт слайсер. Ориентация берётся из STL; модель размещается на столе,
но автоматический поиск поворота не выполняется. Вращение в окне фронта управляет
только камерой. Габариты проверяются до слайсинга и по фактическому расположению после него.
Файл без объёма и модель, не помещающаяся на стол в данной ориентации, отклоняются.

Обозначим минимальные заполнение и периметры как F и W, выбранный слой как H,
а более тонкий слой как h (0.08 / 0.16 / 0.20 для H 0.12 / 0.20 / 0.28).
Сравниваются `(F,W,H)`, `(F,W,h)`, `(F,W+1,H)`, `(F+10,W,H)`, `(F+10,W+1,h)`, `(F+20,W+1,H)`.
Заполнение — gyroid, при 100% — rectilinear. Остальные настройки берутся из профиля.
Это ограниченный и воспроизводимый поиск, а не рекомендация выдерживаемой нагрузки.

Слайсер возвращает `result.json` и временный G-code. Из результата читаются
`total_predication` (секунды, переводятся в минуты) и сумма `total_used_g`.
Проверяются код завершения, одна пластина, конечные положительные значения,
фактические слой/периметры/заполнение и расположение модели. Версия читается из заголовка G-code.
Нагрузка в Н и прочность в МПа в этом ответе отсутствуют.

Сначала отбрасываются варианты, превышающие ограничения пользователя. Затем:

- `MIN_MATERIAL`: минимальные граммы.
- `MIN_TIME`: минимальное общее время.
- `BALANCED`: минимум суммы `time/minTime + mass/minMass` среди допустимых вариантов.

В ответ входят все шесть вариантов с `meetsConstraints`, выбранный ID, параметры
принтера, версия Bambu Studio, предупреждения и описание метода. ID используются только внутри приложения.
Оценка времени включает подготовку из профиля; реальный нагрев и калибровка могут отличаться.
Расход включает сгенерированные поддержки, но не является точным взвешиванием отходов и подготовки принтера.

## Нагрузка на сервер и хранение

- Одновременно выполняется один подбор, шесть запусков слайсера идут последовательно.
- Очереди без ограничения нет: новый запрос при занятости получает 429 `SLICER_BUSY`.
- Успешные одинаковые запросы берутся из кеша по SHA-256 файла и параметрам.
  Кеш в памяти ограничен 32 результатами и 15 минутами; файлы в нём не хранятся.
- Бюджет всего подбора — 180 секунд, одного процесса — не более 45 секунд;
  дополнительно используется собственный предел Bambu Studio `--mstpp 40`.
  Лимиты задаются `PRINTLAB_SLICING_JOB_TIMEOUT_SECONDS`,
  `PRINTLAB_SLICING_PROCESS_TIMEOUT_SECONDS`, `PRINTLAB_SLICING_NATIVE_TIMEOUT_SECONDS`.
  При запуске проверяется `1 ≤ native < process ≤ job ≤ 180`.
  Nginx ожидает до 200 секунд, браузер — до 210 секунд: сервер успевает завершить
  процесс и передать контролируемую ошибку до обрыва HTTP-соединения.
  Зависший процесс и его потомки завершаются, временные каталоги удаляются.
- Тайм-аут отдельного варианта не уничтожает уже рассчитанные варианты.
  Ответ содержит `plannedCandidateCount` и только успешные `candidates`;
  интерфейс явно показывает неполное сравнение. Выбор ограничивается этими
  вариантами и по-прежнему учитывает ограничения времени/массы. Если ни один
  вариант не рассчитан или при неполном сравнении среди готовых нет допустимого,
  возвращается `SLICE_TIMEOUT`; полного вывода «решения нет» по неполным данным нет.
  Ошибки геометрии и недостоверный результат слайсера не маскируются частичным успехом.
- В журнале записываются ID подбора, размеры модели, длительность этапов и,
  при ошибке, последние 2 КиБ диагностики слайсера одной строкой. Исходные
  STL и G-code в журнал не попадают; пользователю внутренняя диагностика не передаётся.
- Каждый процесс получает собственный временный рабочий каталог и `--datadir`.
  STL, конфигурации, G-code и служебные файлы после запроса удаляются.
- На фронте запрос выполняется только по кнопке, повторные нажатия блокируются.
  Смена параметров отменяет ожидание и исключает устаревший ответ.
  Если клиент ушёл, уже начатый серверный расчёт может завершиться в пределах бюджета и попасть в кеш.
- HTTP-ответ — `Cache-Control: no-store`; серверный кеш результатов не публикует модели в браузерный кеш.

`SLICER_UNAVAILABLE` (503), `SLICE_TIMEOUT` (504), `SLICE_FAILED`, `MATERIAL_UNSUPPORTED`,
`MODEL_DOES_NOT_FIT`, `NO_PRINTABLE_VOLUME`, `NO_PRINT_PLAN` (422) имеют понятные сообщения.
Диагностика нативного процесса не передаётся пользователю. Автоматических повторов и опроса статуса нет.

Ограничение одного расчёта действует на один процесс Spring. Для нескольких экземпляров
нужен общий ограниченный worker/очередь. В production слайсер следует запускать в worker
с лимитами памяти/CPU и диска: текущая реализация ограничивает конкуренцию и время,
но не заменяет системные ограничения памяти нативного процесса.

## Запуск и проверка

На macOS при стандартной установке Bambu Studio пути определяются настройками по умолчанию.
Для иной установки задайте:

```sh
PRINTLAB_BAMBU_EXECUTABLE=/absolute/path/to/BambuStudio
PRINTLAB_BAMBU_PROFILES=/absolute/path/to/resources/profiles/BBL
```

При обновлении бинарника или системных профилей перезапустите бэк: разрешённые профили
и успешные результаты кешируются в памяти. Проверено на macOS и Ubuntu 24.04.5 x86_64
с Bambu Studio 02.08.02.61. На Linux используется распакованный официальный Ubuntu 24.04
AppImage, запускаемый через `AppRun`: он задаёт путь к комплектным библиотекам и локаль.
Для расчёта по CLI на этом сервере графический сеанс и видеокарта не потребовались.
Установленная конфигурация и результаты проверки — [live-server.md](live-server.md).
Без установленного слайсера остальные функции приложения работают, а запрос подбора возвращает 503.
Приложение не подключается к принтеру, не отправляет задания печати и не экспортирует пользователю G-code.

Обычные `./mvnw test` проверяют выбор по метрикам, ограничения, кеш, очистку файлов,
конкуренцию, остановку зависшего процесса, чтение результатов и разрешение профилей без настоящего принтера.
Браузерная проверка с установленным Bambu Studio и запущенным бэком:

```sh
E2E_BACKEND=1 E2E_BAMBU=1 npm run test:e2e -- --workers=1
```

`fixtures/stepped-block.stl` на фронте — замкнутая L-образная деталь 30 × 30 × 15 мм,
которой нет в базе испытанных образцов. Она используется для реальной сквозной проверки.
Другие браузерные сценарии проверяют интерфейс на управляемых ответах; тестовые ответы
из `src/test` не используются приложением.
