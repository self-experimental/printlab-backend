## Работа и ограничения

`printlab-backend`, `nginx` и `certbot.timer` включены в автозапуск.
Backend выполняется пользователем `printlab`, Java heap — 1 ГБ.
Java и дочерний слайсер разделяют лимит CPU 300%, MemoryHigh 4 ГБ,
MemoryMax 5 ГБ, TasksMax 256. Файлы приложения доступны службе только для чтения.
`PrivateTmp` отделяет её временные STL/G-code от общих временных файлов сервера.

Один процесс API обслуживает один активный подбор. Успешные результаты кешируются
на 15 минут; перезапуск API сбрасывает кеш. Постоянное сохранение пользовательских
STL в публичном интерфейсе не включено. Все шесть вариантов считаются настоящим
слайсером; оценки прочности для произвольных деталей не добавлялись.

Лимиты времени: native 40 с, процесс 45 с, весь подбор 180 с, Nginx 200 с,
клиент 210 с. Они согласованы между собой. Если отдельный вариант превысил лимит,
готовые допустимые варианты возвращаются с `plannedCandidateCount`; интерфейс
показывает, сколько вариантов успешно рассчитано. Если допустимого результата нет,
запрос завершается контролируемой ошибкой. Ограничения CPU/RAM и одного подбора сохранены.

Telegram-бот ещё не реализован. Исходящий HTTPS к `api.telegram.org` с VPS проверен.
Будущий бот должен работать отдельной службой и использовать этот же API,
с собственным ограничением запросов на пользователя. Токена бота в релизе нет.

## Проверки при размещении

- Каталог содержит 8 материалов и доступен через публичный HTTPS.
- `stepped-block.stl` вне базы экспериментальных образцов даёт 6 вариантов
  на Linux: для PLA выбран гироид, 15%, 2 периметра, слой 0,2 мм;
  оценка 19,085 мин и 3,769 г. Первый серверный подбор занял около 27,5 с.
- PETG при максимальном слое 0,28 мм и без поддержек тоже вернул 6 вариантов.
- Другой запрос во время подбора возвращает `429 SLICER_BUSY`.
- Неизвестные API, постоянная загрузка моделей, запись экспериментов и Swagger
  снаружи возвращают 404; неверный метод расчёта — 405.
- Заявленный размер запроса больше 16 МиБ отклоняется Nginx с
  `413 FILE_TOO_LARGE` без отправки большого тела в API.
- Главная и SPA-маршрут возвращают оболочку приложения; отсутствующий JS — 404.
- Временных каталогов STL/G-code после завершённых расчётов не осталось.
- После обновления Ubuntu и разрешённой перезагрузки вход по ключу, Nginx,
  API и firewall восстановились автоматически; каталог вернул 200.
- Тест `certbot renew --dry-run --run-deploy-hooks` прошёл: подтверждены
  продление сертификата и вызов проверки/перезагрузки Nginx.
- В опубликованном интерфейсе загружен `stepped-block.stl` и выполнен новый
  расчёт после перезагрузки: отображены 3D-модель, 6 строк сравнения и результат
  19,09 мин / 3,77 г. Скриншот проверки: `/private/tmp/printlab-vps-live.png`
  на ноутбуке (временный файл, не часть серверного релиза).

### Проверка исправления тайм-аутов

«корпус_метка.stl», 744 треугольника, габариты 101 × 78 × 176 мм, до исправления
стабильно возвращал `SLICE_TIMEOUT` примерно за 14,08 с. Отдельный вариант
без этого внешнего ограничения успешно считался за 17,8 с.
После исправления публичный HTTPS-запрос завершился с HTTP 200 за 86,66 с:
рассчитаны все 6 вариантов, выбран 15% / 2 периметра / 0,2 мм,
оценка 547,76 мин / 303,85 г. Результат проверен и через опубликованный интерфейс.
Во время диагностики также воспроизведён тайм-аут отдельного шестого варианта;
этот случай покрыт сохранением успешных вариантов и явной маркировкой неполного сравнения.
Проверки релиза: 45 тестов backend, 119 тестов frontend и 6 браузерных сценариев.
Два дополнительных сценария с локальным установленным Bambu Studio пропущены;
настоящий слайсер проверен непосредственно на VPS.

## Обслуживание

Команды выполняются на сервере:

```sh
systemctl status printlab-backend nginx --no-pager
journalctl -u printlab-backend -n 100 --no-pager
nginx -t
systemctl list-timers certbot.timer
certbot certificates
ufw status verbose
df -h /
```

При смене JAR или слайсера проверять каталог и один настоящий расчёт после
перезапуска `systemctl restart printlab-backend`.
Не запускать второй экземпляр API на тех же JSON-файлах.

Исходные конфиги Nginx/UFW перед системной настройкой скопированы в
`/opt/printlab/backups/initial/`. Это локальная копия, не резервирование вне VPS.
Перед будущими изменениями данных сохранять `/var/lib/printlab` отдельно от релизов;
внешнее резервирование ещё нужно подключить при появлении постоянных пользовательских данных.
