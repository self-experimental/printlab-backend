# Подбор по назначению детали

`POST /api/print-plans/analyze-stl` принимает STL и необязательный `description`
(до 2000 символов). Все ручные параметры также необязательны; отсутствующее поле
означает автоматический подбор, а не число 0. Старые запросы с заполненными
полями остаются действительными. Явно выбранные значения имеют приоритет.

## Разбор описания без ключей

Типовые явные назначения распознаются правилами: декоративная деталь, макет для
примерки, рабочая деталь, усиленный профиль, гибкая деталь. Отрицания не обрабатываются
как положительные ключевые слова. Неоднозначное описание передаётся локальной
Qwen3 1.7B через Ollama. Модель возвращает только категорию из фиксированного списка.
Числовые настройки и объяснения определяет код, а не свободный ответ модели.
При неопределённом назначении используется универсальный профиль; модель не может
понизить такой запрос до декоративного, гибкого или чернового профиля.

Это стартовые рекомендации, а не результаты испытаний на прочность. Геометрия
используется слайсером для расхода и времени. Температура эксплуатации, химическая
стойкость и допустимая нагрузка из текста не вычисляются. Для специальных условий
материал следует выбрать вручную. Профили не выдаются за экспериментально
подтверждённые свойства произвольного STL.

Источники подхода: [Slicer Copilot](https://github.com/pfrankov/slicer-copilot),
[настройки PrusaSlicer](https://help.prusa3d.com/category/prusaslicer_204),
[руководство по прочности UW–Madison](https://medesignlab.me.wisc.edu/3d-printing/printing-a-strong-part/).
Чужой исходный код и промпты в проект не скопированы.

## Настройки

- `PRINTLAB_RECOMMENDATIONS_ENABLED=true` включает локальную модель.
- `PRINTLAB_OLLAMA_URL=http://ollama:11434` — внутренний адрес сервиса.
- `PRINTLAB_OLLAMA_MODEL=qwen3:1.7b` — компактная модель с открытыми весами Apache-2.0.
- `PRINTLAB_RECOMMENDATIONS_TIMEOUT_SECONDS=25` — предельное ожидание ответа.

Ключи API не нужны. Описание и STL не отправляются внешнему провайдеру.
Ollama получает только описание; STL остаётся в контейнере бэкенда. Во время
первой установки образ Ollama и веса скачиваются из официальных реестров.
У Ollama нет опубликованного порта, доступ осуществляется внутри сети Compose.

Первый запуск инфраструктуры (до деплоя нового backend image):

```sh
docker volume create printlab-ollama
docker compose --env-file /etc/printlab/compose.env -f /etc/printlab/compose.yaml up -d --no-deps ollama
docker compose --env-file /etc/printlab/compose.env -f /etc/printlab/compose.yaml exec -T ollama ollama pull qwen3:1.7b
```

Официальный образ закреплён по digest. Контейнер ограничен 1,5 CPU и 2304 МБ,
обрабатывает один запрос одновременно; облачные функции отключены.
Загруженная модель освобождается после двух минут бездействия.
На текущем VPS исходная широкая генерация оказалась медленной; в реализации
оставлена только короткая классификация. Типовые назначения не вызывают её вообще.

Разбор защищён тайм-аутом, ограничением ответа 16 КБ, проверкой JSON и перечня
категорий. Один общий слот расчёта охватывает AI и слайсер. Повторный расчёт
того же STL и запроса использует кеш 15 минут; классификация описаний — кеш до
128 записей на один час. Нет автоматических повторов. Текст описания, ответ
модели и CAD не пишутся в логи. При недоступности модели возвращается честно
обозначенный универсальный профиль (`FALLBACK`), а не выдуманный ответ AI.

## Настройки и результат

Базовые профили задают заполнение, стенки, слой, рисунок, верхние и нижние
сплошные слои. Ручной минимум заполнения/стенок сохраняет смысл минимума;
в сравниваемых вариантах допускаются большие значения. Выбранный слой — верхний
предел: соседний вариант может печататься более тонким слоем. Верхние/нижние слои,
рисунок и выбор поддержек фиксированы для всех вариантов. Температуры и скорости
по-прежнему берутся из поддерживаемого профиля принтера и паспорта материала.

Новый объект `recommendation` содержит `source` (`RULES`, `LOCAL_MODEL`,
`FALLBACK`, `DEFAULT`), назначение `purpose`, пояснение `summary` и список
`items: [{title, text}]`. Тексты формируются после выбора реального рассчитанного
варианта, поэтому значения соответствуют `selectedCandidateId`.
У кандидатов добавлены `topLayers`, `bottomLayers`, `supportMode`; рисунок также
поддерживает `GRID` и `CUBIC`. Старые поля ответа сохранены для существующих клиентов.

В интерфейсе рекомендации занимают место прежних общих абзацев. Техническая
информация и предупреждения доступны в раскрываемом блоке «Как получен расчёт».
Изменение описания или ручных параметров отменяет старый запрос и убирает его
результат. Отправка выполняется только по кнопке.
